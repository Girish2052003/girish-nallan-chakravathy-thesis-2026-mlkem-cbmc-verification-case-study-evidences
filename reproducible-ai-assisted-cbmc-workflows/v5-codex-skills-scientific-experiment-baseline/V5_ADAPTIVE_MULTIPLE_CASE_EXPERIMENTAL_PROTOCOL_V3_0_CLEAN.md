**Protocol status:** Frozen working protocol
**Research design:** Exploratory adaptive multiple-case study
**Principal reasoning agent:** OpenAI Codex
**Formal verification tool:** CBMC 6.9.0
**Primary implementation:** `mlkem-native` C
**Authoritative source commit:**

```text

```

**Main investigation:** Whether and how agentic AI can assist end-to-end formal verification of selected ML-KEM production-code targets.

---

# 1. Research purpose

The study investigates whether an agentic coding system can:

1. analyse ML-KEM specification and production-code contexts;
2. formulate meaningful implementation-level candidate theorems or properties;
3. construct CBMC-checkable verification artefacts;
4. execute and interpret CBMC;
5. analyse failures and counterexamples;
6. revise unsuccessful verification approaches;
7. preserve technically useful and reproducible evidence;
8. perform these activities autonomously or with transparently recorded human assistance.

The study also investigates how nine lightweight formal-verification skills support this process without replacing Codex’s reasoning.

The thesis does **not** attempt to establish:

* a statistical ranking of skilled versus unskilled Codex;
* universal performance across all coding agents;
* complete correctness of ML-KEM;
* automatic proof generation without human oversight;
* or global mathematical novelty from CBMC results alone.

---

# 2. Final research questions

These four questions govern the protocol.

> **RQ1:** How can an agentic coding system transform selected post-quantum cryptography specification and production-code contexts into meaningful formal-verification properties and CBMC-checkable artefacts?

> **RQ2:** How can lightweight reusable formal-verification skills support an agentic coding system across the end-to-end verification lifecycle without replacing or unnecessarily restricting its reasoning and autonomy?

> **RQ3:** To what extent can the selected agentic coding system autonomously complete the end-to-end formal-verification lifecycle, and at which stages is human intervention still required?

> **RQ4:** To what extent are the verification artefacts generated by the agentic workflow repository-distinct, technically valid, useful for CBMC-based verification, and supported by adequate evidence, and what failure modes, contamination risks, and reproducibility limitations are observed?

RQ2 is therefore **not**:

> Do the skills outperform unassisted Codex?

It asks how the skills support, fail to support, burden, redirect, or remain unused by Codex.

---

# 3. Research-design classification

The empirical study is classified as:

> **An exploratory, iterative and adaptive Codex-centred multiple-case study involving selected ML-KEM production-code verification targets.**

It combines:

* qualitative within-case analysis;
* cross-case thematic analysis;
* descriptive quantitative summaries;
* artefact inspection;
* CBMC evidence;
* process tracing;
* human-intervention analysis;
* optional matched skilled-versus-unskilled contrasts.

It is not an inferential statistical experiment.

This distinction permits different targets to receive different numbers of runs while still requiring every run and every decision to be documented.

# 5. Unit-of-analysis definitions

To avoid confusion, the thesis will use these terms consistently.

## Case

One of the 14 target function or function-group investigations.

## Run

One independently recorded Codex session conducted for a defined target and purpose.

A run starts with a registered configuration and ends when its autonomous or human-assisted investigation is formally closed.

## Iteration

A command, artefact revision, counterexample investigation or repair performed **inside one run**.

Iterations do not count as separate runs.

## Follow-up run

A new Codex session opened for a documented reason, such as another theorem family, reproducibility examination, parameter replication or recovery from an inconclusive outcome.

## Autonomous phase

The part of a run during which Codex works without substantive human verification guidance.

## Human-assisted phase

A clearly marked continuation in which the researcher supplies technical help after the autonomous evidence has been preserved.

# 6. Roles and authority

## Codex

Codex is the sole principal reasoning agent.

Codex owns:

* source and specification interpretation;
* candidate-theorem selection;
* assessment of property meaningfulness;
* substantive assumption selection;
* assertion design;
* harness strategy;
* CBMC strategy;
* counterexample interpretation;
* repair decisions;
* mutation design;
* final technical explanation.

The V5 design explicitly preserves these responsibilities for Codex rather than distributing them among helper agents. 

## Nine helper skills

All nine skills are available in skill-enabled runs:

1. `mlkem-spec-grounding`
2. `target-build-context`
3. `cbmc-harness-scaffold`
4. `cbmc-execute`
5. `cbmc-counterexample-view`
6. `harness-integrity-audit`
7. `cbmc-nonvacuity-probe`
8. `verification-evidence-manifest`
9. `controlled-mutation-runner`

The skills are:

* optional;
* bounded;
* inspectable;
* non-authoritative;
* bypassable;
* repeatable;
* replaceable by Codex’s own run-local method.

Codex may use none, some or all of them. It is not forced to invoke them in a fixed order.

The architecture keeps Codex as the principal agent while allowing it to use, ignore, repeat or replace the skills. 

## CBMC

CBMC is the formal-tool authority for the exact encoded bounded model.

CBMC may establish that an emitted property passed or failed under:

* the supplied source;
* the selected assumptions;
* the encoded harness;
* the recorded build configuration;
* and the exact command-line bounds.

CBMC does not independently establish:

* global mathematical novelty;
* property relevance;
* assumption justification;
* complete ML-KEM correctness;
* absence of vacuity;
* or scientific usefulness.

## Researcher

The researcher:

* selects and scopes the study;
* launches and observes runs;
* approves permitted operations;
* records interventions;
* preserves evidence;
* performs external contamination review;
* evaluates scientific validity;
* writes the thesis interpretation.

The researcher does not silently perform Codex’s work and later credit that work to Codex.

## 7.3 Principal-agent identity

Codex remains the only principal reasoning agent.

No second GPT planner, critic agent, repair agent or semantic orchestrator is introduced.

Every main run uses the frozen **Common Codex Experiment Prompt v1.1**.

Only target-specific fields may change:

* experiment identifier;
* target;
* configuration;
* source location;
* specification location;
* clean-room location;
* concise target emphasis that does not reveal a theorem or solution.

The substantive scientific instructions remain unchanged.

## 7.5 Solution blindness

The target-specific proof corpus is withheld during independent discovery.

Codex must not inspect or reuse:

* existing target-specific harnesses;
* completed proof packages;
* theorem statements;
* final assumptions;
* successful commands;
* repair histories;
* mutation packages.

The official anti-copy audit occurs only after the run and artefacts are frozen. Exposing an anti-copy oracle during the run could leak information about the hidden reference corpus and encourage cosmetic similarity evasion. 

## 7.6 Evidence preservation

Every run must preserve sufficient evidence to determine:

* what Codex received;
* what Codex did;
* what Codex generated;
* what CBMC checked;
* what failed;
* what changed;
* what the skills contributed;
* what the human contributed;
* and why the result received its classification.

## 7.7 Claim boundary

The study distinguishes:

* AI-generated candidate claims;
* CBMC-generated bounded tool evidence;
* human scientific interpretation.

No one layer silently substitutes for another.

# 8. Flexible protocol elements

These elements are intentionally adaptive.

## 8.1 Number of runs

There is **no predetermined universal run count**.

A target may receive:

```text
1 run
2 runs
5 runs
or another technically justified number
```

The number of runs is decided through the evolving needs of the case study.

The final thesis reports:

* how many runs were actually performed;
* why each run was opened;
* what each run contributed;
* and whether any runs were excluded or classified as invalid.

There is no rule requiring equal run counts across targets.

## 8.2 Assistance configuration

A run may use either configuration:

```text
UNASSISTED_CODEX
SKILL_AVAILABLE_CODEX
```

A target may have:

* only unassisted runs;
* only skill-available runs;
* both configurations;
* multiple runs of one configuration;
* or several runs of both.

The thesis does not require both configurations for every target.

## 8.3 Theorem count

The prompt asks Codex to propose a small, justified candidate set.

The normal range is:

```text
1–4 candidate theorem families
```

This is a planning range, not a quota.

Codex may produce fewer than four when additional candidates would be:

* repetitive;
* artificial;
* trivial;
* ambiguous;
* infeasible;
* or insufficiently grounded.

At least one primary candidate should be selected for complete investigation where technically feasible.

## 8.4 Verification strategy

Codex may choose:

* standard harnesses;
* relational harnesses;
* sequential compositions;
* two-call comparisons;
* round-trip harnesses;
* direct assertions;
* loop or function contracts;
* temporary mathematical checkers;
* diagnostic scripts;
* another justified CBMC-compatible strategy.

## 8.5 Time budget

There is no universal time limit imposed across all functions.

Each run receives a **declared planned budget before it starts**.

The record includes:

```text
PLANNED CODEX SESSION BUDGET:
PLANNED INDIVIDUAL CBMC TIMEOUT:
```

Different targets may receive different budgets because their technical complexity differs.

An extension is permitted, but it must be logged before continuing:

```text
EXTENSION START:
ORIGINAL BUDGET:
ADDITIONAL BUDGET:
REASON:
STATE OF THE RUN WHEN EXTENDED:
```

This provides flexibility without hiding unlimited trial-and-error work.

## 8.6 Human assistance

Human assistance is allowed after the autonomous phase is frozen.

The thesis investigates **AI-assisted formal verification**, not an imaginary requirement that humans disappear completely.

The scientific requirement is transparency—not zero human involvement.

# 9. Assistance configurations

## Configuration U — Unassisted Codex

Codex receives:

* the frozen source;
* supplied specification material;
* common prompt;
* ordinary repository and terminal capabilities;
* CBMC environment;
* declared internet permissions.

The nine V5 skills are not available.

## Configuration S — Skill-available Codex

Codex receives the same materials and environment, with all nine skills available.

Codex decides whether to invoke them.

## Interpretation

The two configurations provide supporting evidence about skill use, but the thesis does not treat Configuration S as a system that must defeat Configuration U.

Direct comparisons are made only where runs are sufficiently comparable in:

* target;
* source;
* configuration;
* task;
* model;
* reasoning setting;
* time context;
* and run purpose.

Unequal adaptive run counts must not be converted into a universal success-rate claim.

The V5 design already recognises that skills may be ignored, distract Codex, increase context burden or leave unassisted Codex performing equally well or better. These are valid findings, not failures of the thesis.

# 11. Permitted reasons for additional runs

An additional run may be opened for one or more of these reasons.

## A. Initial discovery

The first independent examination of the target.

## B. Distinct theorem family

Another substantively different property deserves investigation.

The new property must not be merely:

* renamed;
* cosmetically reformulated;
* divided across coefficients;
* changed through a trivial constant;
* or equivalent to an existing claim.

## C. Follow-up of an inconclusive result

A previous run exposed a meaningful blocker that another independent attempt may clarify.

## D. Reproducibility examination

An important, surprising or technically valuable outcome is repeated to examine whether comparable evidence can be produced again.

## E. Parameter-set replication

For example, PA-06 under:

* ML-KEM-512;
* ML-KEM-768;
* ML-KEM-1024.

## F. Skill-availability contrast

A comparable run is conducted with or without skills to examine differences in process or evidence.

This does not automatically support general causal superiority.

## G. Environment recovery

A run was invalidated by an external setup problem.

The invalid run remains preserved.

## H. Human-assisted continuation

The autonomous phase ended and a new or continued phase is opened with declared human help.

## I. Another documented scientific reason

The reason must be stated before or when the run begins, not invented afterward to justify a favourable outcome.

# 12. Run process

These are **researcher protocol phases**, not mandatory reasoning stages imposed on Codex.

Codex remains free to organise its own work.

## Phase 0 — Registration

Complete the run-registration record.

## Phase 1 — Autonomous investigation

Codex receives the common prompt and works independently.

The researcher may:

* launch the run;
* observe;
* approve actions permitted by the declared environment policy;
* record timestamps and factual observations;
* preserve outputs.

The researcher does not provide:

* theorem suggestions;
* assumptions;
* assertions;
* harness fixes;
* CBMC strategy;
* counterexample explanations;
* repair instructions;
* skill recommendations.

## Phase 2 — Autonomous checkpoint

When Codex finishes, becomes blocked or reaches the declared budget:

* freeze the autonomous artefacts;
* preserve the transcript;
* record the current status;
* record the reason the autonomous phase ended;
* record the amount of work completed.

## Phase 3 — Optional human-assisted continuation

Human help may then be provided.

The transition must be visible:

```text
AUTONOMOUS PHASE ENDED

TIMESTAMP:

AUTONOMOUS STATUS:

AUTONOMOUS FILES FROZEN:

REASON FOR HUMAN ASSISTANCE:

HUMAN INTERVENTION PROVIDED:

FILES OR COMMANDS AFFECTED:

HUMAN-ASSISTED OUTCOME:
```

The autonomous result remains unchanged.

## Phase 4 — End-of-run freeze

Preserve:

* final files;
* hashes;
* commands;
* outputs;
* transcript;
* skill-use information;
* human-intervention log;
* final classification;
* limitations.

## Phase 5 — External evaluation

After the run is frozen, perform:

* technical-validity assessment;
* evidence-completeness assessment;
* repository-distinctness and contamination audit;
* usefulness classification;
* reproducibility assessment.

Observability surrounds Codex rather than prescribing Codex’s semantic route. This separation between common instrumentation and optional assistance is central to V5.

# 13. Stopping conditions

A run ends when one of the following applies.

## A. Supported bounded candidate

Codex has produced:

* a precise primary property;
* explicit assumptions;
* executable artefacts;
* a recorded command;
* selected-claim mapping;
* a CBMC result;
* and sufficient supporting evidence for interpretation.

## B. Meaningful negative result

The run produces a valuable:

* counterexample;
* theorem rejection;
* unsupported-assumption finding;
* source/build limitation;
* tool limitation;
* or other technically informative failure.

## C. Inconclusive result

The run cannot establish or reject the claim, but the unresolved blocker and attempted approaches are recorded.

## D. Declared resource boundary

The current planned or extended budget is reached.

## E. External environment failure

The run is invalidated by an issue not attributable to Codex’s reasoning, such as:

* corrupted common inputs;
* unavailable installation;
* service failure;
* incorrect environment setup;
* missing tool expected by the registered protocol.

## F. Source-integrity violation

The authoritative production implementation is modified, bypassed, stubbed or replaced in order to obtain success.

## G. Contamination

The run substantially accesses or uses withheld target-specific proof material.

* properties proposed;
* grounding in specification and code;
* theorem distinctness;
* assumptions;
* assertions;
* harnesses;
* CBMC-checkable artefacts;

* which skills were available;

* which were ignored;

# 18. Cross-case synthesis

After individual case analysis, the study will examine patterns across:

* simple and complex functions;
* arithmetic and encoding targets;
* single-function and relational cases;
* standard and round-trip properties;
* autonomous and human-assisted outcomes;
* skill-used and skill-ignored runs;
* technically valid and invalid artefacts;
* evidence-complete and evidence-incomplete runs;
* easy and difficult CBMC models;
* successful, negative and inconclusive investigations.

Possible patterns include:

* skills helping mechanical preparation but not reasoning;
* unassisted Codex performing better on complex targets;
* skills improving evidence completeness despite no proof improvement;
* Codex ignoring unnecessary tools;
* relational targets requiring more human help;
* complex arithmetic causing resource or modelling difficulties.

Those are possible findings—not assumptions embedded into the protocol.

# 20. Optional matched contrasts

Where genuinely comparable skilled and unskilled runs exist, a within-target contrast may examine:

* theorem candidates;
* time and iterations;
* artefact readiness;
* source/build accuracy;
* CBMC progress;
* autonomous repairs;
* evidence completeness;
* human intervention;
* failure behaviour.

These comparisons are supporting analyses.

They do not change RQ2 into:

> Which condition wins?

A careful conclusion might be:

> In the examined cases, helper-skill availability improved mechanical support and evidence production in some runs, had limited effect in others, and appeared to burden or redirect Codex in certain complex investigations.

That kind of mixed result is fully compatible with the protocol.

# 21. Handling runs completed before this freeze

Runs conducted before adoption of this final protocol are classified as:

```text
PRE-PROTOCOL EXPLORATORY RUN
```

They are not discarded.

They may contribute as:

* pilot evidence;
* design motivation;
* preliminary observations;
* integration findings;
* case-study context.

A pre-protocol run may be discussed in the results only when its available evidence is sufficient to reconstruct:

* inputs;
* source identity;
* model configuration;
* work performed;
* CBMC result;
* human involvement;
* and artefacts.

It must remain clearly labelled as retrospective or exploratory rather than silently presented as a prospectively registered run.

Your preliminary observation that skills produced mixed effects therefore remains valuable, but it does not modify the final rubric to favour that result.

# 22. Reproducibility under an adaptive design

The protocol does not promise that another Codex session will generate identical reasoning or the same theorem.

It supports three more defensible forms of reproducibility.

## Environment reproducibility

Another researcher can identify:

* source revision;
* tool versions;
* model configuration;
* build configuration;
* input materials.

## Process reproducibility

Another researcher can understand:

* why the run was initiated;
* what prompt was used;
* what actions occurred;
* why the run continued or stopped;
* where human intervention occurred.

## Evidence reproducibility

Another researcher can inspect:

* harnesses;
* assertions;
* assumptions;
* commands;
* CBMC outputs;
* traces;
* manifests;
* hashes;
* final classifications.

Generative output variability is treated as a limitation, not hidden.

# 24. Allowed thesis claims

Subject to the actual results, the thesis may claim:

* agentic AI produced candidate formal-verification properties for selected cases;
* Codex generated CBMC-checkable artefacts;
* some candidates received bounded CBMC support;
* some runs exposed useful failures and counterexamples;
* helper skills provided observable forms of support or limitation;
* Codex completed some lifecycle activities autonomously;
* human intervention remained necessary at identified points;
* artefacts varied in validity, usefulness and evidential strength;
* the approach showed both opportunities and limitations.

---

# 25. Forbidden thesis claims

The thesis must not claim, without appropriate evidence:

* Codex automatically verified ML-KEM;
* every generated theorem was novel;
* repository distinctness proves global novelty;
* CBMC success proves complete correctness;
* the nine skills made Codex smarter;
* the skills generally outperform unassisted Codex;
* unequal run counts establish comparative success rates;
* every target was successfully verified;
* human assistance was absent when it occurred;
* failed runs contain no research value;
* the results generalise automatically to Claude Code or every coding agent.

# 27. Thesis-ready methodology statement

This paragraph can later be adapted into Chapter 3:

> The empirical investigation followed an adaptive multiple-case design rather than a fixed-repetition performance benchmark. Fourteen selected ML-KEM implementation targets formed the planned case registry, and each case was investigated through one or more independently recorded Codex sessions. Run counts were not fixed uniformly because target complexity, candidate-property diversity, tool behaviour, parameter-set replication, unresolved findings and the need for follow-up investigation differed across cases. Before each run, the target, run purpose, source revision, model configuration, assistance configuration and planned resource budget were recorded. Additional runs were permitted only for documented purposes, including investigation of a substantively distinct theorem family, follow-up of an inconclusive result, reproducibility examination, parameter-set replication, environment recovery, human-assisted continuation or examination of optional skill support. All technically meaningful runs, including failed and inconclusive attempts, were preserved. Skill-available and unassisted runs were compared only when sufficiently comparable; unequal adaptive run counts were not used to claim general performance superiority.

The protocol is now:

* **flexible in run count;**
* **flexible in target-specific time;**
* **flexible in verification strategy;**

* research questions;
* target registry;
* Codex’s intellectual ownership;
* solution-blindness;
* source integrity;
* evidence requirements;
* intervention transparency;
* run-registration rules;

* claim boundaries;

That is what makes it both **flexible and thesis-worthy**.
