# RQ2 control-allocation and semantic-authority ledger

This ledger records how procedural governance and semantic authority were allocated across V1–V5.

| Control | Function | Classification | V1 | V2 | V3 | V4 LLM | V4 Codex | V5 | Interpretation |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| RQ2-CTRL-01 | Source identity and frozen-target binding |  |  |  |  |  |  |  | Can remain outside semantic reasoning without selecting the verification claim. |
| RQ2-CTRL-02 | Permission/write boundary |  |  |  |  |  |  |  | Controls filesystem authority rather than theorem/property meaning. |
| RQ2-CTRL-03 | Build/source context capture |  |  |  |  |  |  |  | Useful mechanically, but over-compressed or incomplete supplied context can constrain later reasoning. |
| RQ2-CTRL-04 | Evidence capture, manifests and provenance |  |  |  |  |  |  |  | Preservation is compatible with semantic autonomy because it records rather than selects conclusions. |
| RQ2-CTRL-05 | Typed output schemas |  |  |  |  |  |  |  | Schemas can support reproducibility; they become restrictive if they force semantic decomposition or erase needed context. |
| RQ2-CTRL-06 | Context preparation/compression |  |  |  |  |  |  |  | This is a key transfer dimension because omitted or preselected context may not be recoverable in stateless staged reasoning. |
| RQ2-CTRL-07 | Property discovery / theorem selection |  |  |  |  |  |  |  | The V5 response removes mandatory external semantic ownership of property selection. |
| RQ2-CTRL-08 | Artefact strategy and substantive assumptions/assertions |  |  |  |  |  |  |  | Run 002 demonstrates why semantic origin must be tracked separately from later automation. |
| RQ2-CTRL-09 | Critic approval as progression gate |  |  |  |  |  |  |  | The retained V3/V4 runs show that critic/progression states can stop the workflow independently of model capability. |
| RQ2-CTRL-10 | Formal-tool execution |  |  |  |  |  |  |  | Formal-tool authority should remain distinct from semantic candidate authority. |
| RQ2-CTRL-11 | Counterexample interpretation / diagnosis |  |  |  |  |  |  |  | Separating diagnosis from the continuing reasoning context can impede revisiting earlier assumptions and source interpretations. |
| RQ2-CTRL-12 | Repair selection |  |  |  |  |  |  |  | V5 returns substantive repair choice to the continuing reasoning context while retaining integrity controls. |
| RQ2-CTRL-13 | Stage progression / active semantic stage |  |  |  |  |  |  |  | This is the central allocation changed in V5; causal superiority is not established. |
| RQ2-CTRL-14 | Stopping authority |  |  |  |  |  |  |  | Scientific stopping controls remain necessary, but semantic stopping created by stage/critic mechanics must be distinguished from property-level failure. |
| RQ2-CTRL-15 | Scientific evaluation and final claim authority |  |  |  |  |  |  |  | Neither deterministic code nor the reasoning model is authorised to convert candidate output into unrestricted correctness claims. |
